# InternSetu – Free Deployment Checklist

Stack: **Neon** (PostgreSQL) + **Render** (FastAPI backend, `render.yaml`) + **Vercel** (Next.js web) + **Expo** (mobile).
Free-tier limits change often. Check each provider's pricing page before relying on them.
This is a research demo on synthetic data. Keep the "demo data / not official PMIS" labels visible.

## 0. Before you start
- [ ] Code is on GitHub (private or public) and contains **no** `.env` files (`git ls-files | grep env` shows only `.env.example`).
- [ ] Backend tests pass locally: `cd backend && pytest` (199 passed at session 14). Web: `npx tsc --noEmit && npx vitest run && npx next build`. Mobile: `npx tsc --noEmit && npx jest`.
- [ ] Accounts created: GitHub, Neon, Render, Vercel (and Expo if you want a mobile demo).

> **Session 27:** the Render start command now runs `alembic upgrade head` before the app starts, so tables are created or updated on every deploy. Use a new, empty Neon database. If your database was created some other way, run `alembic stamp head` once from `backend` instead of upgrading.

## 1. Database (Neon)
- [ ] Create a Neon project (region near you, e.g. Singapore or Mumbai if offered).
- [ ] Copy the connection string, e.g. `postgresql://user:pass@host/db?sslmode=require`.
- [ ] Rewrite the start to `postgresql+psycopg2://` so it matches the code:
      `postgresql+psycopg2://user:pass@host/db?sslmode=require`
- [ ] Keep this string private. It is your `DATABASE_URL`.

## 2. Load schema and data (from your own computer)
```bash
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env     # set DATABASE_URL (Neon string from step 1) and a SECRET_KEY (32+ chars)
alembic upgrade head
python -m app.scripts.load_datasets --all
python -m app.scripts.create_admin                      # create your admin account
```
- [ ] Migration finished without errors.
- [ ] Dataset loaded (taxonomy, internships, demo candidates).
- [ ] Admin account created. Do not reuse a weak password.
- [ ] Do **not** commit the `.env` you just edited.

## 3. Backend (Render)
- [ ] Render dashboard: **New + > Blueprint**, pick your repo. Render reads `render.yaml`.
- [ ] When asked, set `DATABASE_URL` to the Neon string from step 1.
- [ ] Set `CORS_ORIGINS` to a temporary value such as `http://localhost:3000` (you update it in step 5).
- [ ] `SECRET_KEY` is generated by Render. Leave `MATCHING_METHOD=baseline` and `WARM_UP=0`.
- [ ] Do **not** install `requirements-ml.txt` on the free plan (torch is too big for 512 MB).
- [ ] Wait for the deploy to finish, then open `https://<your-service>.onrender.com/health` (should say ok).
- [ ] Open `/docs` and confirm the API loads.
- [ ] If the build fails on Python version, change `PYTHON_VERSION` in `render.yaml` to one Render supports.

## 4. Web (Vercel)
- [ ] **Add New > Project**, import the repo, set **Root Directory** to `web`.
- [ ] Environment variable: `NEXT_PUBLIC_API_URL` = `https://<your-service>.onrender.com` (no `/api/v1`, no trailing slash).
- [ ] Deploy. Note the URL, e.g. `https://internsetu.vercel.app`.
- [ ] Vercel's free Hobby plan is for personal, non-commercial use. Fine for a college project.

## 5. Connect the two (CORS)
- [ ] In Render, set `CORS_ORIGINS` to your Vercel URL (add the custom domain too if you have one), then redeploy.
- [ ] Open the Vercel site in a private window and watch the browser console: no CORS errors.

## 6. Smoke test (do this on the live site)
- [ ] Register a new user and accept consent.
- [ ] Fill education, skills, location and sectors.
- [ ] Recommendations show 3–5 results, with the "Close match" tag where relevant.
- [ ] Switch language (English, Hindi, Marathi, Bengali) and check the explanations.
- [ ] **Email is REQUIRED now**: sign-up, password reset and account deletion all use emailed codes, so without SMTP nobody can register on a public site. Email codes: set `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM` on Render (Gmail app password, Brevo or Resend free tiers). Without them codes only appear in the Render log. Send yourself one test code before sharing the link. The code limiter is in memory, so keep **one** backend instance.
- [ ] Log in as admin and open the admin console.
- [ ] `POST /api/v1/pmis/precheck` works from `/docs`.
- [ ] Demo-data notice and "not official PMIS" disclaimer are visible.

## 7. Mobile (optional)
- [ ] In `mobile/.env` set `EXPO_PUBLIC_API_URL=https://<your-service>.onrender.com`.
- [ ] Demo with Expo Go (`npx expo start`), or build an APK with EAS. Check the current EAS free limits first.

## 8. Before a demo or viva
- [ ] Open the backend URL ~2 minutes early. Free Render services sleep after 15 idle minutes and need 30–60 s to wake.
- [ ] Log in once and load recommendations so the database connection is warm.
- [ ] Keep a local copy running (`docker compose up`) as a backup in case the network fails.
- [ ] Have screenshots or a short screen recording ready.

## 9. Security and privacy checks
- [ ] `SECRET_KEY` is random and only stored in Render.
- [ ] No passwords, tokens or `.env` in Git history (if one leaked, rotate it).
- [ ] Neon password rotated if it was ever pasted into chat, screenshots or a public file.
- [ ] No real personal data in the demo. Use fake test accounts only.
- [ ] Login lockout is in-memory (resets on restart). Fine for a demo, not for production.

## 10. Troubleshooting
| Problem | Likely cause / fix |
|---|---|
| First request takes a minute | Free Render service was asleep. Wait, or ping `/health` first. |
| `could not connect` / SSL error | `DATABASE_URL` missing `?sslmode=require`, or still using `postgresql://` instead of `postgresql+psycopg2://`. |
| `SECRET_KEY must be at least 32 characters` | Set a longer `SECRET_KEY`. |
| Browser shows CORS error | `CORS_ORIGINS` does not exactly match the Vercel URL (check `https`, no trailing slash). |
| Web shows "failed to fetch" | Wrong `NEXT_PUBLIC_API_URL`, or backend asleep. Redeploy Vercel after changing env vars. |
| Out of memory on Render | You installed the ML requirements. Use `MATCHING_METHOD=baseline`. |
| Empty recommendations | Data not loaded (step 2) or profile incomplete. |

## 11. Later (when you outgrow free)
- Render Starter or another always-on host (no sleep), Neon paid plan, persistent login lockout (Redis), alembic migration on deploy.
